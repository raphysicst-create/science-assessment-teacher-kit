# 정답 세트 라벨 지침 v1 (1차: 항목·필드, 2026-11-08)

이 지침은 정답 세트 라벨러(Claude 라벨러, astra 라벨러)가 따른다. 두 라벨러는 서로의 결과를 보지 않고 원문만 보고 라벨을 단다.

## 0. 볼 수 있는 것과 볼 수 없는 것
- 볼 것: `data/gold/pack/INDEX.md`, `data/gold/pack/*.md`(원문 변환 묶음), 필요하면 `data/gold/raw/`(원문 사본), 이 지침, `data/reference/gold_label_schema.json`.
- 보지 말 것: `data/derived/`, `scripts/`, `services/`, DB, `data/gold/labels/`의 다른 라벨러 파일, git 기록. 파이프라인 결과를 보면 정답 세트가 오염된다.
- 원문 묶음 한계: HWP·HWPX·ZIP 안 HWP는 kordoc 변환본만 있다(쪽 번호 없음, 표는 HTML/마크다운). PDF는 kordoc 변환본과 PyMuPDF 쪽별 텍스트가 함께 있다. 변환이 의심스러우면 `ambiguous`로 남긴다.

## 1. 이번 차례의 범위
- 대상: 2022 개정 **중학교 1·2학년 교과 '과학'**의 2026학년도 1·2학기 수행평가 **전수**. 자동 추출이 될지와 상관없이 원문에 있는 것 전부.
- 제외: 중3 과학, 다른 교과(기술·가정, 환경, 정보, 체육 등), 자유학기 주제선택·동아리·창체, 정기시험(지필평가)과 그 안의 서·논술형 문항.
- 활동 축(탐구·실험평가 등)은 이번에 달지 않는다. 활동 정의(S8) 확정 뒤 2차로 단다.

## 2. 무엇이 항목 하나인가
- 평가계획이 **따로 반영비율이나 만점을 주는 수행평가 영역·과제 하나**가 항목 하나다. 예: 요약표의 `힘의 작용 탐구(20)` 한 줄.
- 한 과제 안의 채점 요소, 단계, 루브릭 수준은 항목이 아니라 그 항목의 필드다.
- 같은 항목이 요약표와 세부 계획표에 두 번 나오면 **항목 하나**에 위치를 둘 다 적는다(`occurrences`). 같은 항목이라는 근거(같은 제목, 과제번호, 같은 비율 등)를 `identity_basis`에 적는다. 근거가 약하면 따로 두고 `ambiguous`에 이유를 적는다.
- 1학기 공시 문서가 연간 계획이라 2학기 항목도 있고, 2학기 공시에도 같은 항목이 있으면 역시 항목 하나에 위치를 모두 적는다. 판본이 달라 값이 다르면 6절의 `conflict`로 둔다.
- 자유학기라 비율이 없어도 교과 '과학'의 평가 과제로 적혀 있으면 항목이다. `free_semester: true`, 비율은 `source_absent`.
- 학기는 **평가가 이뤄지는 학기**다. 공시 회차(1차=1학기, 3차=2학기)와 다를 수 있다.

## 3. 문서 기록
`data/gold/pack/INDEX.md`의 문서마다 `type: "document"` 줄을 하나씩 쓴다. 과학과 무관한 문서도 쓴다(`science_sections: []`).
- `edition`: `valid`(유효), `superseded`(같은 학교·학년·학기의 다른 판본으로 대체됨), `conflict`(판본끼리 내용이 달라 어느 쪽이 유효한지 원문으로 알 수 없음). 근거를 `edition_note`에.
- `science_sections`: 중1·2 과학 평가 부분마다 `{grade, semester, line_start, line_end}`. 끝 줄은 다음 교과·학년이 시작하기 직전 줄.
- `notes`: 특이 사항(요약표만 있음, 분할 파일, 변환 의심 등).

## 4. 항목 필드
값은 **원문 그대로**(`raw`) 적는다. 띄어쓰기·괄호·기호를 고치지 않는다. 숫자로 바꾼 값은 `norm`에 따로 적는다. 원문에 없는 값을 만들지 않는다.
- `title`: 항목을 부르는 셀이나 줄의 글. `role`은 `평가영역`(예: 실험, 탐구), `과제명`(구체 과제), `번호`(수행평가1처럼 번호뿐), `기타`. 평가영역 제목과 구체 과제명이 둘 다 있으면 제목은 평가영역 칸 값, 과제명은 `task_text`에 따로.
- `task_no`: 과제번호(원문 표기 그대로).
- `period`: 평가 시기(원문 그대로).
- `method`: 평가 방법. 체크란이 있으면 선택지마다 `{text, state}`. `state`는 `checked`, `unchecked`, `no_box`(체크란 없음), `unreadable`. 체크 기호는 원문 그대로 `mark`에. 기타 칸 괄호 내용은 `other_text`, 체크란 없이 평문으로 쓴 방법은 `plain_text`.
- `standards`: 성취기준. 원문 표기(`raw`, 예 `[9과05-01~03]`), 펼친 코드(`codes`, 예 `["[9과05-01]","[9과05-02]","[9과05-03]"]`), 성취기준 문장이 같이 있으면 `text`. 코드 없이 영역명만 있으면 `area_name_raw`에 적는다. 이 항목에 귀속된다는 근거 위치를 `loc`에. 범위 표기를 펼칠 수 없으면 `ambiguous`.
- `max_score`: 만점. `sub_scores`: 채점 요소별 배점(요소명과 점수). `ratio`: 반영비율(원문 값과 단위, 예 `20%`, `20`).
- `rubric`: 채점기준(성취수준·루브릭) 표가 있으면 위치 범위와 이 항목에 연결된다는 근거.
- `free_semester`: 자유학기 평가면 `true`.

## 5. 필드 상태
필드마다 `status`를 단다.
- `present`: 원문에 있고 이 항목의 값이라는 근거가 있다.
- `source_absent`: 이 항목에 해당하는 원문 부분을 다 봤는데 그 값이 없다.
- `ambiguous`: 값이 있는 것 같지만 어느 항목 것인지, 무슨 값인지 원문으로 확정할 수 없다. `note`에 이유.
- `conflict`: 원문의 두 곳(요약표와 세부표, 두 판본 등)이 서로 다른 값을 준다. `values`에 둘 다 위치와 함께 적는다. 하나를 고르지 않는다.

## 6. 위치
- 위치 `loc`는 `{doc_id, line}` 또는 `{doc_id, line_start, line_end}`. 줄 번호는 `data/gold/pack/<doc_id>.md` 파일의 1부터 센 줄 번호다(`grep -n` 기준).
- PDF는 아는 경우 `page`도 적는다(묶음의 `<<<PAGE n>>>` 표지 기준).
- 같은 값이 여러 곳에 있으면 모두 적는다.

## 7. 출력
- 한 줄에 JSON 하나(JSONL). 줄 종류는 `document`, `item` 두 가지.
- 항목 키 `item_key`는 `<school_id>-g<학년>-s<학기>-<순번>`(순번은 원문 등장 순서, 01부터).
- 스키마는 `data/reference/gold_label_schema.json`. 제출 전 `scripts/gold_validate.py`로 검사하라는 지시가 있으면 따른다(라벨러는 결과 파일만 검사하고 스크립트 내용은 읽지 않는다).
- 끝에 요약: 학교별 문서 수, 항목 수, `ambiguous`·`conflict` 수, 의심스러운 변환.
