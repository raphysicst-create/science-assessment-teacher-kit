# 정답 세트 라벨 지침 v2 (2차: 활동 축, 2026-11-09)

이 지침은 정답 세트 **활동 라벨러**(Claude 라벨러, astra 라벨러)가 따른다. 두 라벨러는 서로의 결과를 보지 않고 원문만 보고 라벨을 단다. 활동 정의는 `docs/science_activity_definitions.md`(정의 버전 **activity-def-v1**)이고, 이 지침은 그 정의를 항목 83개에 적용하는 절차다.

## 0. 볼 수 있는 것과 볼 수 없는 것
- 볼 것: `data/gold/activity/items_v1.jsonl`(항목 83개 묶음), `data/gold/pack/<doc_id>.md`(원문 변환 묶음, 항목의 `occurrences`가 가리키는 문서·줄), `data/gold/pack/INDEX.md`, 활동 정의 문서, 축 파일 `data/reference/science_axes.json`, 이 지침, 라벨 스키마 `data/reference/activity_label_schema.json`.
- 보지 말 것: `data/derived/`, `scripts/`, `services/`, DB, `data/gold/activity/labels/`의 다른 라벨러 파일, `data/gold/labels/`(1차 라벨 원본), `data/gold/gold_v1*.jsonl`, git 기록. 파이프라인 결과를 보면 정답 세트가 오염된다.
- 묶음(`items_v1.jsonl`)에는 정답 v1에서 확정된 항목 필드(제목·역할·과제 설명·평가 방법·채점기준 위치·성취기준 코드·자유학기)가 들어 있다. 활동 판정에 쓰되, 원문 줄을 반드시 직접 읽는다(묶음에 없는 평가요소·채점기준 문장이 원문에 있을 수 있다).

## 1. 무엇을 다는가
- 항목 83개 전부에 활동 라벨 한 줄씩. 항목은 새로 만들거나 합치지 않는다(1차 라벨에서 확정됨).
- 라벨 = **주활동 1개(또는 기권)** + **보조활동 0개 이상** + 근거.
- 활동 10개 이름(정확히 이 표기): 탐구, 실험평가, 작성, 제작, 분석, 추론·설명, 발표·토론, 계산·측정, 과정평가, 문제해결.
- 단원 축은 이번에 달지 않는다(성취기준 코드·영역명에서 코드로 계산한다).

## 2. 판정 절차 (정의 문서 2절 R1~R9를 그대로 따른다)
1. **체크값**: 항목의 평가 방법 칸에서 체크된 선택지를 모은다. 정의 문서의 '표지 분류' 표로 바꾼다. 평가 주체·편성 표지(교사 관찰 및 기록, 교사평가, 자기평가, 동료평가, 개별/모둠 등)는 활동 근거가 아니다. '보고서' 계열은 형식 표지다. '기타( )'는 괄호 내용으로 분류한다.
2. **평문 방법**: 체크란이 없고 방법이 평문이면(예: `보고서형`, `모둠/개별평가`, `실험 평가`) 같은 표로 바꾼다. 아무 활동도 가리키지 않는 평문(`모둠/개별평가`)은 평가 주체 표지로 본다.
3. **방법어 제목·영역**: 1·2가 없으면 제목·평가영역이 방법어(포트폴리오, 실험·실습, 탐구 보고서, 과학 글쓰기, 과학 논술, 프로젝트, 서·논술형, 구술·발표, 탐구활동)인지 본다.
4. **요소 투표**: 과제 설명·평가요소·채점기준 문장마다 정의 문서의 활동별 '요소 사전'과 대조해 맞는 활동마다 1표. 제목도 한 문장으로 센다(제작 동사로 끝나는 제목은 제작 2표, 목적어가 노트·포트폴리오·보고서·계획서·글·일기·시나리오면 0표). 문제해결 사전은 '서·논술형 문제', '문항', '문제해결력' 같은 말이 든 문장에는 표를 주지 않는다. 투표 결과를 `votes`에 적는다(선택이지만 권장).
5. **주활동**: R5(체크 1개) / R6(체크 2개 이상) / R7(체크 없음) 규칙으로 정한다. 기권이면 `primary: null`과 `abstain_reason`(근거 없음 / 근거 동률 / 체크 여러 개·요소 근거 없음 / 체크 판독 불가).
6. **보조활동**: 주활동을 뺀, 체크 기본 활동과 표 1 이상인 활동. 표 수 내림차순.
7. **근거**: 판정에 쓴 원문을 `evidence`에 적는다. `type`은 checkbox / method_text / assessment_area / rubric / title_verb. `quote`는 원문 글자 그대로(띄어쓰기·기호 수정 금지), `loc`는 `{doc_id, line}` 또는 `{doc_id, line_start, line_end}`(그 항목의 `occurrences` 문서 안). 주활동이 있으면 evidence는 1개 이상.
8. 요약표만 있고 세부표가 없는 학교(제목·비율만)는 1~3단계 근거만으로 판정하고, 없으면 기권 '근거 없음'. 억지로 제목 뜻을 해석해 활동을 만들지 않는다. 제목 동사만 있는 경우는 title_verb 근거로 판정한다(정의 문서의 발표·토론 포함 사례 「열팽창을 활용한 예를 발표하기」 참고).
9. 정의가 비어 있거나 두 활동 사이에서 규칙으로 못 가르는 경우는 규칙대로 기권 또는 기본 활동을 택하고 `note`에 "정의 빈칸: …"으로 이유를 적는다. **정의를 임의로 보완해 판정하지 않는다.** 빈칸은 불일치 판정 단계에서 정의 버전을 올려 다룬다.

## 3. 출력
- 파일: 지시받은 경로(`data/gold/activity/labels/<라벨러>.jsonl`). 한 줄에 JSON 하나, 83줄, `item_key` 순서는 묶음과 같게.
- 필수 키: `item_key`, `definition_version`("activity-def-v1"), `primary`, `secondary`, `evidence`. 선택: `abstain_reason`(기권이면 필수), `votes`, `rule_applied`(적용한 규칙 번호, 예 "R5-③"), `note`.
- 제출 전 `.venv/Scripts/python.exe scripts/gold_activity_validate.py <파일> --expect-version activity-def-v1`을 돌리라는 지시가 있으면 따른다(라벨러는 결과만 보고 스크립트 내용은 읽지 않는다).
- 끝에 요약: 주활동 분포(활동별 개수·기권 수), 정의 빈칸으로 느낀 것 ≤5줄.
