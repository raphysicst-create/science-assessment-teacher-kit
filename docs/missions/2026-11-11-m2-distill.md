1. 활동 AI 묶어 보내기: 지시문 대부분(활동 정의)이 같아 카드 5장을 한 번에 보내면 `ax-run` 호출이 약 80% 줄어든다(묶음 4~6 전체로 약 40%). N1의 묶음 방식 F1 0.899 < 카드 단위 0.9115라서, 같은 개발 세트와 반복 측정으로 다시 잰 뒤에만 쓴다.
2. `cc-run` 증류: 제외 5.5%(과제 아님 67·중복 56·합침 16 / 2,503). 중복은 코드로 판정할 수 있다. "제외 없음"이 확실한 묶음을 고르는 게이트를 같은 방식(학교 단위 나누기)으로 잴 수 있다.
3. 묶음 4~6이 끝나면 `rule_applied == "규칙 확신→AI 생략"` 카드 수와 N3 맹검에서 켠 판 품질을 확인한다. 검수자 지적: 평가 하한 0.9641은 불일치 1건으로 정해진다.
4. 빌드 단계(`round_records`)까지 건너뛴 카드의 `activity_axes_rule_version`·`rule_applied`를 확인하는 테스트(검수 제안).
5. hybrid summary의 `item_count`가 건너뛴 카드를 세지 않는다(검수 제안).

## 회고
① 산출물 기준: 증류 게이트는 "학습 쪽에서만 고르고(평가 기준보다 엄격하게), 평가 쪽 하한까지 넘고, 실행 코드 함수를 분석이 그대로 import해 같은 조건임을 코드로 보인다"가 좋은 결과물이다. 절감은 단계 몫(ax-run 51%)을 곱해 전체 호출 기준으로 말해야 기대와 맞는다(ax-run 12% → 전체 6%).
② 작업 방법: 규칙 증류의 상한은 AI 자기 반복 일치(0.965)다. 증류를 시작하기 전에 "규칙과 AI 전체 일치"와 "AI 반복 일치"부터 보면 기대 절감을 미리 알 수 있다. 실행기 캐시가 있는 단계에 게이트를 넣을 때는 "응답이 이미 있으면 건너뛰지 않는다"로 앞 묶음 결과를 고정한다. Codex read-only 샌드박스가 1909로 막히면 재시도해도 같으니 바로 읽기 전용 Claude 워커로 바꾼다. Bash에서 `cat >`를 heredoc 없이 쓰면 stdin을 기다리며 멈춘다(10분 낭비).
③ 브리프에 빠졌던 것: "AI 사용을 얼마나 줄일 수 있나"의 상한(반복 일치)과, 규칙 증류 말고 호출 방식(묶어 보내기)이 훨씬 큰 지렛대라는 점. 이번엔 범위 밖으로 막혀 있어 숫자를 낼 수 없었다. 검수자 환경이 막혔을 때 대체 검수자를 쓸 수 있는지도 브리프에 없었다.
④ 사용량: Codex 0(구현은 부서장이 함), astra 2회 호출(둘 다 환경 실패), Claude 읽기 전용 워커 1회(약 12만 토큰), 유료 0, 약 37분(12:06~12:43).
⑤ 사용자에게: 규칙으로 줄일 수 있는 몫은 전체의 약 6%다. 더 줄이려면 활동 판정을 카드 여러 장씩 묶어 보내야 하는데, 이건 품질을 다시 재야 하는 방향 결정이다.
