# S6d-2e 항목 쪼개짐·조각·필드 공유 보강

## 1. 진단표

[진단표](2026-11-09-s6d2e-diagnosis.md)에 원문 표·줄 구조와 조치 근거를 기록했다.

| 유형 | 진단 | 처리 |
|---|---|---|
| 세부 배점·성취기준 쪼개짐 | 하나의 제목 병합셀 아래 방법·점수·코드가 세부 열로 나뉨 | 제목 셀의 소유 열을 한 항목으로 묶고 총점·세부 배점·성취기준을 필드로 보존 |
| 연속 표 | 같은 과제 아래 반복 form 또는 뒤 채점표가 별도 후보가 됨 | 같은 제목·필드 근거·새 머리글 없는 연속성을 확인. 다른 과제번호·새 머리글은 분리 |
| 조각 제목 | ‘혈액의수’처럼 불완전 수행과제 셀이 제목으로 채택됨 | 최소 길이·조사 말미·미완 어절 검사로 제목 근거에서 제외 |
| 공유 성취기준 | 장흥유치 1학기는 실제 PDF도 네 영역을 가로지르는 하나의 기준 셀 | shared 근거로 보존. 항목별 기준 값은 빈 목록·unconfirmed. 줄 정렬로 배분하지 않음 |
| PDF 2학기 | 학년 표지가 라벨 조각표 앞에 있어 숫자표 바로 앞만 찾던 정렬이 실패 | 앞 조각표 이전까지 확인하되 마지막 학년 표지와 물리 PDF 학년이 일치해야 복원 |
| 영역명 제목 | ‘과학 논술’이 일반 영역명으로 분류되지 않음 | 온전한 구체 수행과제 셀을 대표 제목으로 우선하고 영역명은 assessment_area에 유지 |

갈산 중2 1학기 용해도는 직전 S6d-3c에서 이미 bounded로 복구되어 있었다. 이 작업의 전후 모두 2개가 대응한다.

## 2. 바꾼 파일·일반 규칙

- `scripts/middle_items.py`: 규칙 버전 `middle-items-v13`. 제목 셀을 기준으로 하위 열을 합치며 과제번호가 다르면 합치지 않는다. 병합된 총점은 score, 방법별 배점은 sub_scores에 보존하고 채점 수준을 합산하지 않는다. 같은 표의 반복 form과 같은 과제 머리글 아래 인접 필드표를 연결한다. 분리 근거가 없는 별도 셀의 반복 활동 제목은 검토로 보낸다. 일반 영역명의 반복은 실제 과제명 반복과 구별한다. 제목 조각 검사와 ‘과학 논술’ 영역 처리를 추가했다. 항목 ID 규칙은 기존 v2를 유지한다.
- `scripts/middle_pdf_summary.py`: 제목 열 안에 온전히 들어오는 성취기준 rectangle만 해당 열 소유로 인정한다. 나눌 수 없는 셀은 shared로 남긴다. 앞 라벨 조각표 이전의 학년 표지를 확인하여 1·2학기 같은 복원 규칙을 적용한다. 값은 유일하게 대응하는 변환 원문 범위에서만 취한다.
- `scripts/middle_identity.py`: 요약의 일반 영역명과 상세의 구체 과제가 다를 때, 유일한 영역명에 더해 정확히 같은 성취기준 집합과 배점 근거가 있어야 연결한다. 공통 방법명만으로 연결하지 않으며 공유 코드 집합은 항목 확정값으로 쓰지 않는다.
- `scripts/compare_middle_performance_items.py`: 여러 하위 열을 소유하는 항목을 감사할 때, 실제 제목 셀이 그 열 전체를 덮는지 먼저 입증한다.
- `scripts/compare_middle_s6d2e.py`: 세 회차 재실행·보관·쪼개짐 집계·64칸 재대조·잔여 전수 표본 생성. 제목 정규화, 원문 줄과 코드의 동시 대응, 또는 검토자별 개별 원문 범위에 있는 문자 그대로의 제목으로 대응한다. 공통 요약표 줄만으로 대응하지 않으며 조각 제목을 대응 근거로 삼지 않는다.
- `scripts/verify_middle_s6d2e.py`, `scripts/validate_middle_s6d2e.py`: 금지 자료와 외부 네트워크 차단, 전체 회귀 전후 비교, 원문·기하·소유·표본·보관본·하드코딩 감사.
- `services/math-assessment-api/tests/test_middle_s6d2e.py`: 학교 독립 합성 21개. 배점·코드 하위 열, 반복 form, 연속 필드표, 새 머리글·과제번호 경계, 약한 반복 제목, 조각 음성, 영역명과 구체 과제, PDF 성취기준 분할·shared, 두 학기·학년 표지 복원을 검사한다.
- `services/math-assessment-api/tests/test_middle_s6d2.py`: 기존 공유 성취기준 테스트의 기대를 항목별 확정값에서 shared·unconfirmed로 변경했다. 제목·시기의 기존 공유 근거 검사는 유지했다.

## 3. 전후 수치와 보관

직전 S6d-3c 결과 JSON·Markdown 6개를 `data/derived/items/*.prev-s6d3c.*`로 보관했다. 보관본 지표가 직전 보고서와 일치하는지 재확인했고 SHA-256을 validation.json에 기록했다. 현재 결과는 같은 폴더의 회차별 JSON·Markdown이다.

## 4. 개발 참고 64칸 재대조

전후 모두 대표 판본 하나와 같은 대응 규칙을 적용했다. 판독 불가 3칸은 정량 분모에서 제외했다. 네 차례 astra 목록의 대조 가능 항목은 147개다.

| 개발 표본 | 찾음 전→후 | 놓침 전→후 | 잘못·중복 전→후 |
|---|---:|---:|---:|
| 1차 16칸 | 35→35 | 0→0 | 0→0 |
| 2차 16칸 | 34→34 | 0→0 | 0→0 |
| 3차 16칸 | 38→38 | 0→0 | 0→0 |
| 4차 16칸 | 35→40 | 5→0 | 5→0 |
| 합계 64칸 | 142→147 | 5→0 | 5→0 |

개발 찾음·정밀도는 각각 142/147(97%)→147/147(100%)다. 네 번째 표본만 보면 35/40(88%)→40/40(100%)다. 원문 줄의 실제 영역명으로 항목 대응을 확인한 경우도 포함한다. **필드 정확도나 모든 제목의 구체성을 평가한 수치가 아니며, 이미 개발 참고로 사용한 칸의 재대조다.**

칸별 전후·대응 근거·미매칭 목록은 [재대조 Markdown](2026-11-09-s6d2e-recheck.md)과 같은 이름의 JSON, 회차별 지표·쪼개짐 ID는 [비교 Markdown](2026-11-09-s6d2e-comparison.md)과 같은 이름의 JSON에 있다.

## 5. 마지막 독립 표본

[원문·대조 표본 Markdown](2026-11-09-s6d2e-review-sample.md) · [JSON](2026-11-09-s6d2e-review-sample.json)

보충 두 회차의 80칸에서 앞선 64칸을 제외한 **잔여 16칸 전부**다. 무작위 재추출이나 bounded 유무에 따른 선별을 하지 않았다. 일반 판본 선택 규칙의 대표 판본 하나를 사용한다.

1절은 원문·변환 경로, 학년·학기와 참고 범위, 문서 전체 확인 목록만 담았다. 과학 구간 밖 평가표가 있을 수 있으므로 문서 전체를 확인하도록 명시했다. 2절에만 파이프라인 bounded를 넣었다. 64칸과 비중복, 80칸 모집단의 완전한 잔여, 1절 값 누출 0과 파이프라인 재현을 감사했다. 새 표본의 독립 원문 판정은 수행하지 않았다.

## 6. 새 위험·남은 한계

- 짧은 실제 과제명도 최소 길이·어절 검사에서 검토로 이동할 수 있다. 일반 영역명·명시적 과제번호는 구별하지만 새 독립 표본에서 실제 누락을 확인해야 한다.
- 제목 셀과 연속 표를 합치는 범위가 넓어졌다. 다른 과제번호·새 머리글·비연속 문구를 경계로 쓰며, 같은 이름의 별개 활동은 여전히 검토 가능성이 있다.
- 장흥유치 1학기의 네 항목은 원문이 실제로 공유 기준을 제시한다. 개별 성취기준을 이 요약표만으로 확정하지 않았다. 코드 귀속을 강화하면서 요약·상세 동일성이 미확정으로 남는 경우가 늘 수 있다.
- 갈산 2학기처럼 수행과제 문장 자체가 평문과 조각 셀로 끊긴 PDF는, 온전한 셀이 있는 경우와 달리 구체 문장을 자동 합성하지 않았다. 영역명 또는 검토 상태가 남을 수 있다. ‘혈액의수’는 대표 제목에서 제거됐다.
- 마지막 16칸의 정확도는 아직 측정하지 않았다. 교육과정 매핑·원문 내부 불일치의 교육적 타당성 확정은 범위에 포함하지 않았다.

## 7. 검증

금지된 정답 디렉터리·이름 패턴과 `2026-11-09-s6d3c-field-sample.*`는 실행 guard로 차단했다. gold 이름의 합성 회귀 테스트도 포함하여 `-p no:cacheprovider`로 전체를 실행했다. 시작 1,029개 중 1,011 통과·기존 실패 18개, 최종 **1,050개 중 1,032 통과·같은 기존 실패 18개·새 실패 0개**다. 신규 합성 21개는 모두 통과했다.

최종 감사 위반·금지 접근·외부 네트워크·하드코딩 grep·좌표 분기 grep은 모두 0이다. 변환 text 323개 해시, 보관본 6개 해시·기준 지표, PDF 셀 기하와 원문 대응, 필드 소유권, 공유 기준 확정값 0, 64칸 및 잔여 16칸 재현을 확인했다. Windows asyncio의 내부 루프백 IPC는 기존 회귀 기준과 동일하게 허용했다.

변경 Python 9개 ruff 통과, `git diff --check` 통과, `git status --short`와 `git diff --stat`를 변경 목록과 대조했다. 기존 S6d-2d 개발 자료의 내용 변경도 0이다. 시작 전부터 있던 미추적 `data/.gold-before-acl-fix/`, `data/gold/`, `data/reference/gold_label_schema.json`, `data/rosters/`는 이번 변경과 구분했다.

검증 결과: `data/derived/s6d2e/validation.json`, 회귀 로그·실패 목록: 같은 폴더의 `pytest-{before,after}.{json,log}`.

