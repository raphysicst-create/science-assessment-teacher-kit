# S6e-2 신호 기반 AI 읽기 대상

2026-11-09

## 구현과 산출물

`scripts/middle_ai_read.py targets`의 기본 모드는 `gaps`다.
`targets --mode all`은 S6e-1과 같은 창·대상 ID·지시문 해시를 생성한다.
두 모드는 다음 경로를 사용한다.

| 모드 | 대상 목록 | 지시문·집계 |
|---|---|---|
| gaps | `data/derived/ai_read/<round>/targets.jsonl` | 같은 폴더의 `prompts/`, `summary.json` |
| all | `data/derived/ai_read/<round>/all/targets.jsonl` | `all/prompts/`, `all/summary.json` |
| 포괄 측정 | 같은 회차의 `coverage.json` | 사람이 확인할 표는 `coverage.md` |

기존 루트 대상이 S6e-1 형식이면 gaps 생성 전에 `all/`에 복사해 보존한다.
기존 보관본과 대상 목록이 다르면 중단한다. gaps 대상 ID에는 별도 버전 문자열을 쓴다.
같은 문서·줄 범위라도 all 응답을 gaps 응답으로 이어 쓰지 않는다.
gaps를 다시 생성할 때도 원문·대상·지시문 해시가 같은 응답만 이어 쓰는 기존 검사를 적용한다.
루트의 예전 지시문 파일이 남아 있어도 실행 목록은 현재 `targets.jsonl`로 결정한다.

## 신호의 정의

| 신호 | 조건 | 선택 범위 |
|---|---|---|
| G1 | S5 과학 구간이 없고 평가계획 본문에 과학 교과 표지가 있음 | 기존 `(b)` 규칙의 표 전체 또는 표지 앞뒤 60줄 |
| G2 | 학교·회차·학년 1/2·학기에 bounded performance가 없고 해당 학년을 담을 수 있는 과학 문서가 있음 | 해당 학년·학기와 양립하는 과학 구간. 학년 구간을 못 찾으면 문서 전체 |
| G3 | `candidate_role=performance`이며 `extraction_status!=bounded` | 소속 과학 구간. 구간이 60,000자 초과면 항목 앞뒤 120줄 |
| G4 | 과제를 가리키는 summary 계열 행에 bounded performance 연결이 없음 | 소속 과학 구간 |

S6 실제 출력에서 개요는 `table_role=summary`, 중복 개요는
`candidate_role=summary_duplicate`로 나타난다. `candidate_role=summary`도 허용한다.
G4는 제목이 있는 행을 검사하고 `identity_relation.detail_item_id`가 같은 문서의
bounded performance를 가리키는지 확인한다. 행 자체가 bounded performance이면
이미 확정된 것으로 처리한다. 상대 항목이 review이거나 ID가 사라졌으면 미연결이다.

G2는 해당 회차 전체 규칙 항목에서 학교별 빈 칸을 계산한다.
문서의 학년 후보가 비면 학년 미상으로 취급한다. 학기 후보가 비면 1·2학기를 검사한다.
학년 구간이 있으나 학기가 명확히 다른 경우에는 그 학기용 문서로 선택하지 않는다.
학년·학기 미상 구간은 후보를 열어 둔다.

창은 사이에 최대 20줄이 비어 있으면 합친다. 합친 창이 길면 기존 60,000자 상한,
최소 3,000자 겹침, 원문 줄 경계 분할을 적용한다. 신호가 없는 bounded 전용 구간은
독립 창을 만들지 않는다. 다른 신호 창에 함께 들어온 bounded 항목의 ID는
각 조각의 `bounded_item_ids`에 기록한다.

각 조각은 `signals`, `signal_evidence`, `selection_mode=gaps`를 기록한다.
`signal_evidence`에는 원래 신호 창과 항목·구간 ID 또는 빈 칸 학년·학기가 남는다.
합쳐진 창의 신호 목록은 그 창에서 파생한 조각들에 계승한다.
신호별 집계는 합쳐진 창 하나가 신호를 여러 개 가지면 각각 센다.
AI 지시문 템플릿과 이벤트 감사 함수는 기존 버전을 사용한다.

## 신호 포괄 측정

`coverage`는 `load_references`로 독립 확인 다섯 번의 80칸을 읽는다.
각 회차는 40칸이다. 같은 과제가 다른 참고 칸에도 나오면 칸별 관찰로 센다.
현재 참고 목록 행 수와 총괄 확인 수가 다른 칸은 없다.

bounded 짝짓기는 다음 순서를 사용했다. 교육적 동일성의 확정은 총괄 검토 대상이다.

1. S6e-1의 정규화 제목·별칭 일대일 대조를 적용한다.
2. 제목이 다르면 참고가 지정한 같은 문서에서 제목 근거 위치 또는 공백만 다른 제목을
   대조한다. 여러 과제가 공유하는 개요 줄도 제목 근거 위치가 특정되면 사용할 수 있다.
3. 남은 후보는 다른 참고 과제가 공유하지 않는 근거 줄과 겹치는 항목을 대조한다.
   제목 근거 위치가 겹치는 후보와 detail 역할을 우선한다.
4. 참고 행과 bounded 항목이 서로 하나씩인 짝만 연결한다. 공통 개요 범위만 겹쳐
   여러 짝이 가능한 경우는 미해결로 남긴다. 연결 근거와 항목 ID는 `coverage.json`의
   `pairings`에 보존한다.

제목만 대조하면 미대응은 53개였다. 문서·위치 대조로 48개를 추가로 연결했다.
남은 5개는 확정된 짝이 없는 참고 행이며, 이 가운데 모호한 개요 연결도 포함될 수 있다.
참고 위치는 인용 줄 속 제목을 먼저 찾는다. 제목 철자가 달라 찾지 못하면 인용 줄의
문자 범위로 계산하고 `reference_line_range`라고 표시한다.

## AI 위치와 병합

새 `locator`는 제목이 들어 있는 근거 하나의 범위다.
세부표는 `seen_in=detail` 또는 해당 원문 표의 수행 과제·평가요소·채점기준·평가기준
표제로 식별해 우선한다. 나머지 근거 사이에서는 `title_line`을 담는 범위와 짧은 범위를
우선한다. 인용문에 제목이 없고 인용 줄 범위에만 있으면 해당 줄 범위를 사용한다.
전체 근거는 `locators` 및 AI 항목의 `owned_ranges`에 보존한다.
겹침 조각의 중복 제거도 범위를 합집합으로 넓히지 않는다.

이전 검증 산출물에 `locator_basis`가 없으면 병합할 때 `title_locator`를 담는
가장 짧은 근거를 다시 선택한다. 원래 근거 목록은 보존한다.

병합은 같은 문서·ZIP 자식에서 대표 locator의 겹침을 검사한다.
규칙의 grade·semester가 None이면 해당 필드만 와일드카드로 취급한다.
값이 있으면 기존처럼 같은 값이어야 한다. 와일드카드로 맞춘 관계는
`scope_wildcards`에 규칙 ID와 사용 필드를 기록한다.
규칙 항목 객체는 그대로 복사하며 원래 학년·학기를 채워 쓰지 않는다.

## 총괄 실행 명령

저장소 루트의 PowerShell에서 실행한다. `<ISOLATED>`는 기존 격리 조건을 만족하는
`D:/workspace` 밖의 빈 폴더 절대경로다. 생성한 gaps 대상은 회차 루트에 있다.

```powershell
.venv/Scripts/python.exe scripts/middle_ai_read.py run --round-key 2026-round-1-dev2 --isolated-cwd "<ISOLATED>" --workers 4
.venv/Scripts/python.exe scripts/middle_ai_read.py verify --round-key 2026-round-1-dev2
.venv/Scripts/python.exe scripts/middle_ai_read.py merge --round-key 2026-round-1-dev2
.venv/Scripts/python.exe scripts/middle_ai_read.py evaluate --round-key 2026-round-1-dev2

.venv/Scripts/python.exe scripts/middle_ai_read.py run --round-key 2026-round-3-dev2 --isolated-cwd "<ISOLATED>" --workers 4
.venv/Scripts/python.exe scripts/middle_ai_read.py verify --round-key 2026-round-3-dev2
.venv/Scripts/python.exe scripts/middle_ai_read.py merge --round-key 2026-round-3-dev2
.venv/Scripts/python.exe scripts/middle_ai_read.py evaluate --round-key 2026-round-3-dev2
```

AI 호출 없이 다시 측정하려면 다음 명령을 쓴다.

```powershell
.venv/Scripts/python.exe scripts/middle_ai_read.py targets --round-key 2026-round-1-dev2 --mode gaps
.venv/Scripts/python.exe scripts/middle_ai_read.py coverage --round-key 2026-round-1-dev2
.venv/Scripts/python.exe scripts/middle_ai_read.py targets --round-key 2026-round-3-dev2 --mode gaps
.venv/Scripts/python.exe scripts/middle_ai_read.py coverage --round-key 2026-round-3-dev2
```

## 검증과 남은 위험

- S6e-1·S6e-2 합성 테스트 89개가 통과했다. 전체 회귀는
  `.venv/Scripts/python.exe -m pytest -p no:cacheprovider --tb=no`로 실행해
  1,213개 통과, 기존 실패 18개, 새 실패 0개였다. `test_gold_score.py`를 포함한
  gold 합성 테스트도 포함했다. 기존 실패는 카탈로그 DB 부재에 따른 API·데이터 실패다.
- 변경 Python 파일 3개의 ruff, `git diff --check`가 통과했다.
  생성한 77개 조각의 원문 줄 좌표·60,000자 상한·지시문 해시도 확인했다.
  구현·지시문에서 실제 학교명, 실제 파일 해시, 참고 제목 리터럴 하드코딩은 각각 0건이다.
- Git 변경 대상은 구현, 기존 합성 테스트 fixture, 새 합성 테스트, 이 문서의 4개다.
  시작부터 있던 미추적 데이터 경로들은 상태 목록과 대조했다.
- G1~G4 양성·음성, bounded 전용 구간 제외, 학교 단위 빈 칸, 학년 미상,
  긴 구간의 120줄, 20줄 인접 병합, 60,000자 분할·3,000자 겹침을 합성 검증한다.
- 제목 근거 선택, 세부 우선, 중복 제거 후 소유 근거 보존, 이전 합집합 산출물 복구,
  None 학년·학기 관계 표기, 다른 문서 위치 배제, 모호한 개요 짝짓기를 검증한다.
- all 대상·지시문 해시와 gaps의 별도 ID·재생성 안정성을 검증한다.
- `py -3`는 설치된 Python을 찾지 못해 기존 `.venv/Scripts/python.exe`를 사용했다.
- 신호가 없는 조용한 규칙 오확정은 gaps에서 빠질 수 있다. 현재 80칸의 포괄 결과는
  그 밖의 문서에 대한 보장을 제공하지 않는다.
- 문서·위치 짝짓기는 교육적 의미 판단을 대신하지 않는다. 특히 공통 개요 범위와
  대표 제목 차이는 `pairings`를 원문과 함께 검토해야 한다.
- G1은 학년 필터를 추가하지 않아 중3 문서의 표지 창도 포함한다.
  세부표 판별은 기존 응답 스키마에 근거별 역할이 없어서 원문 표제를 이용한 추정이다.
- all 비교본과 실제 생성 대상은 `data/derived/`의 기존 Git 제외 규칙을 따른다.
  이 작업은 실제 AI 응답 품질을 측정하지 않았다.
