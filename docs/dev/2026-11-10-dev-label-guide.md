# 개발 표본 활동 라벨 지침 (개발용, 정답 아님, 2026-11-10)

이 지침은 **개발 표본**(개발 12개교 `2026-round-3`, 보충 20개교 `2026-round-1-dev2`·`2026-round-3-dev2`)의 수행평가 항목 258개에 활동 라벨을 다는 Claude 라벨러가 따른다. 정답 세트 라벨 지침 `docs/gold/label_guide_v2_activity.md`의 절차를 그대로 쓰되, 경로와 정의 버전만 다르다. 이 라벨은 분류기 개선의 **개발 지표**에만 쓴다. 정답이 아니다.

## 0. 볼 수 있는 것과 볼 수 없는 것
- 볼 것: `data/dev_labels/items_dev.jsonl`(항목 묶음, 한 줄=한 항목), `data/dev_labels/pack/<doc_id>.txt`(변환 원문 전문, 줄 번호 붙임), `docs/science_activity_definitions.md`(정의 **activity-def-v2**), `data/reference/science_axes.json`, 이 지침.
- 보지 말 것: `data/derived/`, `data/gold/`, `scripts/`(검사기 실행은 허용, 내용 읽기는 금지), `services/`, `apps/`, DB, `data/dev_labels/labels/`의 다른 파일, `docs/missions/`, `docs/dev/`의 다른 문서, git 기록. 파이프라인 결과를 보면 라벨이 분류기에 끌려간다.
- 묶음에는 항목을 찾는 데 필요한 것만 있다: `item_id`, 학교·학년·학기, 파이프라인이 읽은 `title`(식별용), `doc_id`, 원문 줄 범위 `line_start`·`line_end`, 발췌 `excerpt`(앞 5줄·뒤 45줄 포함, 줄 번호 붙임). 평가 방법 체크(☑/□)·평가요소·채점기준·과제 설명은 **발췌 원문에서 직접** 읽는다. 발췌가 모자라면(채점기준 표가 더 뒤에 있는 등) `pack/<doc_id>.txt`의 그 주변을 더 읽는다.

## 1. 무엇을 다는가
- 묶음의 항목 전부에 활동 라벨 한 줄씩. 항목은 새로 만들거나 합치지 않는다.
- 라벨 = **주활동 1개(또는 기권)** + **보조활동 0개 이상** + 근거.
- 활동 10개 이름(정확히 이 표기, 가운뎃점 `·` U+00B7): 탐구, 실험평가, 작성, 제작, 분석, 추론·설명, 발표·토론, 계산·측정, 과정평가, 문제해결.
- 단원 축은 달지 않는다.

## 2. 판정 절차 (정의 문서 2절 R1~R10을 그대로 따른다)
1. **체크값**: 발췌의 평가 방법 칸에서 체크된 선택지(☑, ■, ● 등 채워진 표시)를 모은다. 정의 문서 '표지 분류' 표로 바꾼다. 평가 주체·편성 표지(교사 관찰 및 기록, 교사평가, 자기평가, 동료평가, 개별/모둠 등)는 활동 근거가 아니다. '보고서' 계열은 형식 표지. '기타( )'는 괄호 내용으로 분류한다.
2. **평문 방법**: 체크란이 없고 방법이 평문이면 같은 표로 바꾼다. 아무 활동도 가리키지 않는 평문은 평가 주체 표지로 본다.
3. **방법어 제목·영역**: 1·2가 없으면 제목·평가영역이 방법어(포트폴리오, 실험·실습, 탐구 보고서, 과학 글쓰기, 과학 논술, 프로젝트, 서·논술형, 구술·발표, 탐구활동)인지 본다(R3).
4. **요소 투표**(R4): E층 = 제목(1단위) · 평가영역 칸(1단위) · 평가요소 칸·과제 설명 칸(글머리·번호·가운뎃점·'및' 나열은 항목마다 1단위). S층 = 채점기준 표의 요소마다 최고 수준 문장 하나. 성취기준별 성취수준 표·진도표·학생 유의사항은 세지 않는다. 단위마다 활동 사전과 대조해 활동마다 최대 1표(공백 무시, 어간 일치). 제목이 제작 동사로 끝나면 제작 2표(목적어가 노트·포트폴리오·보고서·계획서·글·일기·일지·시나리오·발표 자료면 0표). 투표 결과를 `votes`에 적는다(E층·S층 합쳐도 되지만 `votes_e`·`votes_s`로 나누면 더 좋다).
5. **주활동**: R5(체크 1개) / R6(체크 2개 이상) / R7(체크 없음). 기권이면 `primary: null`과 `abstain_reason`(근거 없음 / 근거 동률 / 체크 여러 개·요소 근거 없음 / 체크 판독 불가).
6. **보조활동**(R8): 주활동을 뺀, 체크 기본 활동과 표 1 이상인 활동. 표 수 내림차순.
7. **근거**: 판정에 쓴 원문을 `evidence`에 적는다. `type`은 checkbox / method_text / assessment_area / rubric / title_verb. `quote`는 원문 글자 그대로(띄어쓰기·기호 수정 금지), `loc`는 `{"doc_id", "line"}` 또는 `{"doc_id", "line_start", "line_end"}`(pack 텍스트의 줄 번호). 주활동이 있으면 evidence는 1개 이상.
8. 요약표만 있고 세부표가 없는 항목(제목·비율만)은 1~3단계 근거로만 판정하고, 없으면 기권 '근거 없음'. 제목 뜻을 해석해 활동을 만들지 않는다. 제목 동사만 있으면 title_verb 근거로 판정한다.
9. 규칙으로 못 가르면 규칙대로 기권 또는 기본 활동을 택하고 `note`에 "정의 빈칸: …"을 적는다. **정의를 임의로 보완해 판정하지 않는다.**
10. 파이프라인이 읽은 `title`이 원문과 다르거나 항목이 아닌 것(평가방법 행, 점수 처리 규정, 성취기준 문장 등)으로 보이면 라벨은 규칙대로 달되 `note`에 "항목 의심: …"을 적는다. 이 메모는 항목 추출 개선에 쓴다.

## 3. 출력
- 파일: 지시받은 경로(`data/dev_labels/labels/<라벨러>.jsonl`). 한 줄에 JSON 하나, 묶음과 같은 `item_id` 순서.
- 필수 키: `item_id`, `definition_version`("activity-def-v2"), `primary`, `secondary`, `evidence`. 선택: `abstain_reason`(기권이면 필수), `votes`(또는 `votes_e`·`votes_s`), `rule_applied`(예 "R5-③"), `note`.
- 제출 전 `.venv/Scripts/python.exe scripts/dev_activity_validate.py <파일> --expect-version activity-def-v2`를 돌려 errors가 비면 끝낸다.
- 끝에 요약: 주활동 분포(활동별 개수·기권 수), 정의 빈칸으로 느낀 것 ≤5줄, "항목 의심" 수.
