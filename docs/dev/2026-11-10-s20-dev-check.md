# S20 개발 확인 표 (완료 기준 1, 2026-11-10)

개발 자료는 fresh3·fresh4 6개교(이미 본 학교)다. 정답은 astra가 원문으로 먼저 적은 과제 77개(`docs/gold/2026-11-10-fresh3-astra-quality.md` P01~P31, `…-fresh4-astra-quality.md` T01~T46)를 코드로 옮긴 키 `docs/dev/2026-11-10-s20-dev-key.json`(`scripts/dev_task_key.py`)이다. 정답 라벨(`data/gold/`, `data/gold2/`)은 열지 않았다. AI 호출 모델은 S19·S20 모두 `gpt-6.1-terra`.

## 측정 방법(코드)
- `scripts/dev_recall_check.py --database <공개판> --key <키>`: 공개 카드를 astra 과제와 원문 위치(고유 줄 → 공유 줄+제목 → 제목)로 짝짓고, 방법(정규화한 집합 일치)·활동(astra 판정에서 만든 허용 활동)을 판정 표로 낸다. 표는 S19와 같은 합산 스크립트 `scripts/count_astra_card_verdicts.py`로 센다.
- **검사기 검증**: 같은 명령을 S19 공개판(`36226cb41c27cc3c`)에 돌리면 fresh4 25/46으로 astra 판정과 같고, 놓친 21과제가 astra 3절 목록과 같다. fresh3은 31/31(S19 개발 확인의 놓침 9/9 회복과 일치), 짝 없는 카드 0. 출처 `.tmp/s20/devrecall-s19.json`.
- 분모: 재현율은 astra 원문 과제 수(31·46·77), 정밀도는 개발 6개교 공개 카드 수.

- 짝 없는 카드 0, 같은 과제 중복 카드 1(T01이 공산중 1학년 2학기 합친 카드 3장에 모두 들어감 — S19와 같은 카드), 합친 카드 3.
- **남은 놓침 7(fresh4)**: 모두 오수중 1학년 2학기 "1~7차 탐구활동". 원문에 탐구활동별 비율·만점이 없어 AI가 지시문의 과제 단위 규칙대로 영역 하나(`탐구활동`)로 적었고, astra는 7개로 셌다. 과제 단위 정의 차이라 한 학교 예외 규칙을 넣지 않았다(edu 산출물 기준 1).
- **방법 빈칸 11(fresh4)**: 원문 체크 상태를 코드가 못 읽어 비운 것(오수중 1학기 체크 표 6장 등), AI가 낸 방법 줄이 과제 근거 범위 밖이라 버린 것(공산중 3장). 틀린 값은 0이다. 범위를 넓히면 이웃 과제 방법이 붙을 위험이 있어 백로그로 둔다.
- **활동 F1 미달(검수 판정, 뒤집지 않음)**: 완료 기준의 "유지"를 S20 결과로 재면 0.899로 0.92에 못 미친다. 원인 관측: 문맥을 빼도 0.904이고, 고정 S18 DB 입력에 S20 변경만 얹으면 0.929다. S19 대비 하락(0.924→0.899)의 대부분(→0.904)은 입력 변화로 보이고, 같은 S20 입력에서 문맥은 0.904→0.899로 −0.005(1~2장)다. 입력 변화는 새 카드가 같은 학교·학기 묶음에 들어오고 AI 우선 방법 값이 채워져 활동 AI 지시문이 바뀌면 terra가 같은 묶음의 다른 카드 활동도 다르게 답한다(문맥 없이도 S19 대비 4장 맞힘·6장 틀림). 라운드 예산(2/2)이 끝나 이번에 고치지 않는다. 다음 방법 후보: 활동 AI를 카드 하나씩 부르거나 묶음을 고정해 입력 변동을 줄이는지 한 번 잰다(백로그).
