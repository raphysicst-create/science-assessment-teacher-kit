# S6e-3 AI 과제의 필드 채우기

2026-11-09

## 구현

`scripts/middle_ai_fields.py`에 필드 처리와 그림자 비교를 분리했다.
기존 `middle_ai_read.py`에는 하위 명령 등록과 실행 산출물 폴더 지정만 추가했다.
실행 산출물 폴더 인자를 생략하면 기존 실행 경로를 사용한다.

### A단계 규칙 재사용

`source_tables`의 실제 셀 좌표와 제목 evidence locator를 대조한다.
과학·학년·학기 구간 안의 검증된 표에 `row_structures`, `column_structures`,
`form_structures`, `split_form_labels`, `split_standard_forms`, `coalesce_forms`,
`connect_tables`를 적용한다. 행형·열형은 구간 경계가 표 일부를 자르는 기존 사례도 처리한다.
각 빌더의 제목 claim이 제목 칸을 포함하는 구조를 센다.
유일한 구조의 `finalize` 결과 중 present·source_absent만 가져온다.
구조가 겹치거나 제목이 확정되지 않으면 B단계 대상으로 남긴다.

기존 모듈의 필드 처리인 `enrich_claims`, `detail_form_claims`, `sub_score_field`,
`mark_source_absence` 등은 `finalize`를 통해 그대로 적용된다.
원래 규칙이 연결 표의 채점기준을 확정하지 못하면 그 칸도 B단계로 넘어간다.
필드마다 `fill_method="rule_reuse"`를 붙이고 중첩 배점 evidence까지 AI item_id로 소유자를 바꾼다.

`free_semester`는 같은 구간에 기존 `free_semester_field`를 적용한다.
유일한 표 구조가 없어도 학년·학기 구간을 확인할 수 있으면 이 판단을 기록한다.
이 함수의 false 반환도 present 규칙 판단으로 보존한다.
구간 소속 자체가 모호하면 해당 필드를 unconfirmed로 남긴다.

### B단계 창 구성과 실행

지시문은 `scripts/prompts/middle_ai_fields_v1.md`다.
원래 과제를 찾은 `targets.jsonl`의 창을 사용한다.
한 창의 AI 과제를 함께 주고 과제별로 item_id, 제목, title_line, 학년·학기,
원문 근거, requested_fields, 다른 과제 제목 목록을 제공한다.
한 과제가 여러 원래 창에서 발견되었으면 각 창에 포함된다.

대상 필드는 task_text, method, timing, standards, score, weight, sub_scores,
rubric, assessment_area다. A단계의 미확정 칸만 요청한다.
원문을 문서 전체 줄 번호와 함께 제공하고 값마다 줄 범위와 인용을 요구한다.
근거 부재와 불확실성을 구분하고 원문 밖 지식과 도구 호출을 금지한다.

`run_targets`를 그대로 호출한다. 실행 인자는 격리 폴더 `-C`, `-s read-only`,
`--json`이며 기본 workers는 4, timeout은 900초다.
기본 모델 가드, 이벤트 허용 목록, 도구 이벤트 무효화, prompt·answer·events 해시,
유효 응답 이어 하기 모두 기존 구현을 통과한다.
필드 답도 기존 감사기가 읽는 tasks·uncertain JSON 배열 계약을 따른다.

### 원문과 값 대조

지정한 줄과 창 안에서 인용이 원문과 정확히 일치해야 한다.
`literal_span`으로 변환문 offset을 계산한 뒤 원문 철자와 경계까지 추가 확인한다.
NFKC만 같고 실제 글자가 다른 인용은 거부한다.
동일한 인용이 한 줄에 반복되면 표 소유 판정으로 하나만 특정되는 경우에 받는다.
필요하면 evidence에 원문 시작 offset인 start를 제공할 수 있다.

- score·weight는 완전한 숫자 토큰을 대조한다. 10을 100에서 찾지 않는다.
- timing·task_text·assessment_area는 정규화한 원문 인용의 부분 문자열을 대조한다.
- method는 각 값의 부분 문자열과 기존 `method_literal`을 모두 확인한다.
- standards는 정확한 `[9과NN-NN]` 철자, 인용 안의 코드, `reference_codes()`를 확인한다.
- sub_scores는 요소명과 점수가 같은 인용에 함께 있어야 한다.
  이 조건은 여러 셀에 나뉜 요소명·점수에 대해 보수적으로 작동한다.
- rubric은 인용 evidence locator를 `field_locations.rubric` 배열에도 기록한다.

필드의 인용 하나라도 실패하면 그 답 전체를 버린다.
겹치는 창의 통과 값이 서로 다르면 필드를 미확정으로 남긴다.
같은 칸을 여러 AI 과제가 주장하면 필드 종류가 달라도 모두 버린다.
잘못 소속시켜 거부된 단일 칸 주장도 이 충돌 검사에 참여한다.
shared_span으로 입증된 공통 칸만 공유할 수 있다.

### 표 소속 판정

`source_tables`가 rowspan·colspan을 확장한 좌표를 사용한다.
인용이 하나의 검증된 표 칸 안에 완전히 들어가야 한다.

| 정렬 | 수락 근거 |
|---|---|
| same_column | 열형 제목 claim 또는 명시적인 제목 라벨 행으로 확인된 같은 과제 열 |
| same_row | 행형 제목 claim 또는 명시적인 제목 머리글로 확인된 같은 과제 행 |
| own_table | 제목이 있는 단일 과제 서식표 또는 기존 연결 규칙으로 이어진 표이며 인용 칸의 구조 소유자가 유일함 |
| shared_span | 병합 칸이 현재 과제와 다른 알려진 과제의 행·열을 함께 포함함 |
| prose | 표 밖의 원문이며 이 과제 근거 범위에 포함되고 다른 과제 근거 범위와 겹치지 않음 |

열형 표 안의 다음 제목 라벨 행은 새 과제 블록의 경계다.
같은 열이라도 그 경계를 넘어간 값을 거부한다.
own_table 판정 시 표 안에 다른 알려진 과제 제목이 있으면 거부한다.
다른 정렬을 입증할 수 없는 경우 사유는
`AI 항목 읽기: 표 위치로 소속 확인 불가`다.
수락한 AI evidence마다 다섯 정렬 중 하나를 `ai_alignment`에 기록한다.

### 상태와 병합

absent 응답은 `unconfirmed`와 `AI: 원문에 없다고 답함(미검증)`을 기록한다.
답이 없으면 `AI 항목 읽기: 답 없음`, 실패한 답은 `AI 항목 읽기:`로 시작하는 사유를 쓴다.
규칙의 자유학기 판단이 true이면 미확정 score·weight·sub_scores에
규칙 reference_evidence를 absence_evidence로 보존하고 source_absent를 적용한다.
기존 규칙에서 source_absent를 얻은 필드는 먼저 보존된다.

`fields-rule`은 rule.json에 A단계 결과를 둔다.
`fields-merge`에서 검증한 결과를 items_ai에 반영한다.
실행자가 결과를 검토할 수 있도록 병합 전까지 원래 파일을 보존하는 구성이다.

병합은 원본 JSON의 AI 항목 구간만 교체한다.
규칙 항목의 원문 JSON 바이트를 전후 비교하고 item_id 순서·집합과 ai_relations를 대조한다.
하나라도 다르면 실패한다. AI 공개 상태는 false로 유지한다.
최초 병합 전 파일을 `<round>.prev-s6e3.json`으로 보관한다.
같은 디렉터리에 일반 파일로 쓰고 rename하여 최종 파일을 교체한다.

ai_fields_summary에는 필드별 rule_reuse·ai_read·버림 사유·absent·미확정 수와
수락 evidence의 정렬별 수가 들어간다. 버림은 응답 시도 수, 비어 있음은 최종 항목 수다.
답 없음은 비어 있음으로 집계한다. 합성 실행 기록은 simulated로 표시한다.

## 총괄 실행 명령

저장소 루트 PowerShell에서 실행한다. `<ISOLATED>`는 기존 격리 검사에 맞는
`D:/workspace` 밖의 빈 폴더 절대경로다.

```powershell
$rounds = @('2026-round-1-dev2', '2026-round-3-dev2')
foreach ($round in $rounds) {
  .venv/Scripts/python.exe scripts/middle_ai_read.py fields-rule --round-key $round
  .venv/Scripts/python.exe scripts/middle_ai_read.py fields-targets --round-key $round
  .venv/Scripts/python.exe scripts/middle_ai_read.py fields-run --round-key $round --isolated-cwd "<ISOLATED>" --workers 4
  .venv/Scripts/python.exe scripts/middle_ai_read.py fields-verify --round-key $round
  .venv/Scripts/python.exe scripts/middle_ai_read.py fields-merge --round-key $round
}

foreach ($round in $rounds) {
  .venv/Scripts/python.exe scripts/middle_ai_read.py fields-shadow --round-key $round --sample 36 --seed 6173
  .venv/Scripts/python.exe scripts/middle_ai_read.py fields-run --round-key $round --shadow --isolated-cwd "<ISOLATED>" --workers 4
  .venv/Scripts/python.exe scripts/middle_ai_read.py fields-verify --round-key $round --shadow
}
```

같은 targets로 fields-run을 다시 실행하면 유효한 응답은 해시 대조 후 재사용한다.
`fields-verify --shadow`가 그림자 비교 명령도 겸한다.
정답 회차 잠금은 기존 `MIDDLE_AI_READ_GOLD=chief-measurement` 가드를 그대로 사용한다.

## 검증과 남은 위험

합성 테스트는 `services/math-assessment-api/tests/test_middle_s6e3.py`에 있다.
원문·옆 열·같은 칸 충돌·colspan·rowspan·행형·세부표·연결 표·산문·숫자·코드·방법,
rubric 위치·absent·자유학기·A단계 모호성·병합 불변·감사·해시 이어 하기·층화·학교 상한,
실제 CLI 처리 함수의 생성→검증→병합과 그림자 비교를 검증한다.

표 구조와 원문 인용을 보수적으로 대조하므로 미확정 칸이 많이 남을 수 있다.
인용이 여러 위치에서 동등하게 소속되거나 요소명·배점이 다른 셀에 나뉜 경우도 여기에 해당한다.
AI 응답의 실제 정확도와 원문상 의미 적합성은 총괄의 실제 실행·그림자 원문 판정으로 확인한다.
현재 행형 bounded 표본이 없어 개발 그림자 비교의 행형 관찰 범위는 합성 테스트다.

이 환경의 `py -3`는 설치된 Python을 찾지 못했다.
실행에는 저장소의 `.venv/Scripts/python.exe`를 사용했다.

최종 검증 결과는 다음과 같다.

- 새 합성 테스트 39개 통과.
- 전체 회귀 1,302개 통과, 기존 실패 18개, 새 실패 0개.
  기존 실패는 catalog·detail·district·health·reference API 계열이다.
- 변경 Python 3개 파일의 ruff와 `git diff --check` 통과.
- 개발 두 회차의 items·items_ai 총 4개 파일 SHA-256 동일.
- 생성 프롬프트의 원문 줄·60,000자 제한·해시·요청 필드 목록·과제별 제외 목록 검증 통과.
- 두 회차를 합친 그림자 표본의 학교당 4개 상한 검증 통과.
- 새 구현·지시문·합성 테스트의 실제 학교명·새 AI 과제 제목·원문 문서 식별자 하드코딩 검색 0건.
- `git status --short`와 `git diff --stat` 확인 완료.
  작업 파일은 기존 CLI 1개와 새 구현·지시문·테스트·본 문서 4개다.
  시작 때 표시된 미추적 데이터 경로는 별도 변경 목록으로 구분했다.

```powershell
.venv/Scripts/python.exe -m pytest -p no:cacheprovider
.venv/Scripts/python.exe -m ruff check scripts/middle_ai_read.py scripts/middle_ai_fields.py services/math-assessment-api/tests/test_middle_s6e3.py
```
