# 전국 중학교 과학판 실행 계획 (S20, 2026-11-10)

전국판(사용자 확정, 약 3,200개교 × 2회차)을 한 번에 끝까지 돌리기 위한 계획이다. 숫자는 이번 임무(S20)에서 실제로 잰 값과 그 값으로 낸 추정이다. **이 임무는 전국 수집을 시작하지 않는다**(브리프 멈춤 조건). 다음 임무가 이 계획으로 돌린다.

## 2. 전국판 추정 (3,200개교 × 2회차 = 6,400 학교·회차)
| 항목 | 계산 | 추정 |
|---|---|---|
| AI 호출 수 | 6,400 × (2.48 + 0.52 + 2.05 + 2.05) = 6,400 × 7.1 | **약 45,400호출** |
| AI 호출 시간 합 | 6,400 × (2.48×20.3 + 0.52×42.8 + 2.05×15.3 + 2.05×10.1) ≈ 6,400 × 125초 | 약 222시간 |
| AI 단계 실제 소요(동시 8) | 222시간 ÷ 8 | **약 28시간** |
| 수집 | 6,400 × 2초 | 약 3.6시간 |
| 변환·구간·교과·규칙 | 6,400 × 12초(한 프로세스) | 약 22시간(시도 묶음 3개 병렬이면 약 7~8시간) |
| 공개판 빌드·감사·게이트 | 카드 약 32,000장(학교·회차당 5.0장) | 빌드·감사 수십 분, 카드 상세 전수 검사 약 2~3시간(457장 2분 비례) |
| 합계(단계를 겹치지 않을 때) | | **약 40시간**. 시도 단위로 수집·변환과 AI 단계를 겹치면 약 30시간 |
| 저장 용량 | 6,400 × 20MB | **약 130GB**(D: 여유 1.9TB) |

- 위 값은 개발·새 학교 58개교의 평균이다. 큰 학교·ZIP 묶음(교과별 파일 수십 개)은 변환 시간이 더 걸린다. 첫 시도 묶음에서 다시 재고 표를 고친다.
- 유료 사용 0: AI 호출은 Codex 앱 내장 실행 파일(terra)이다. 사용 한도는 4절.

## 3. 시도별로 끊는 순서
학교 수는 다음 임무 1단계(전국 명단 만들기)에서 확정한다. 나이스 학교정보 API는 키 없이 5행만 주므로 학교알리미 `search_school`(시도·시군구·중학교)로 시군구마다 명단을 받고 학교 코드를 붙인다(fresh5와 같은 방법).

| 순서 | 묶음 | 이유 |
|---|---|---|
| 0 | 명단 만들기(전 시도, 수집 없음) | 학교 수·코드 확정. 이미 쓴 표본 학교(개발·정답·fresh) 표시 |
| 1 | 세종·제주 | 학교 수가 적다. 전 단계(수집→공개판 빌드→게이트)를 작은 규모로 한 번 끝까지 돌려 시간표를 다시 잰다 |
| 2 | 울산·대전·광주 | 광역시 중간 규모, 실측 보정 |
| 3 | 강원·충북·충남·전북 | 군 지역 소규모 학교가 많다(문서 형식이 다양) |
| 4 | 부산·대구·인천 | 대도시 |
| 5 | 전남·경북·경남 | 학교 수가 많은 도 |
| 6 | 서울·경기 | 가장 크다. 마지막에 둬 앞 묶음에서 나온 문제를 고친 뒤 돌린다 |

- 묶음마다 끝에 공개판 감사·렌더러·카드 상세 검사를 그 묶음 카드에 돌리고, 차단이 있으면 다음 묶음으로 넘어가기 전에 원인만 기록한다(규칙을 묶음에 맞추지 않는다).
- 정답 회차(gold·gold2)와 fresh 표본 학교는 전국 명단에서 같은 학교가 나와도 회차 키가 달라 따로 남는다. 공개판에서 같은 학교가 두 번 보이지 않게 명단 단계에서 표시하고 하나만 쓴다(다음 임무 결정).

## 4. 중단 뒤 이어 돌리기 · 사용 한도
| 상황 | 지금 코드가 하는 것 | 이어 돌리는 법 |
|---|---|---|
| 수집 중 중단 | 학교마다 영수증(`school_receipts/<학교>-NNNN.json`)을 쓰고, 영수증이 있는 학교는 건너뛴다. 학교알리미가 접근 제한·서비스 응답을 주면 스스로 멈춘다(`paused after Schoolinfo access restriction`) | 같은 명령 그대로 다시. 실패 학교만 다시는 `--retry-failed`. 접근 제한으로 멈췄으면 1시간 이상 쉬고 다시(간격은 기본값 유지) |
| 변환·구간·규칙 중단 | 회차 단위로 다시 만든다(변환은 `--reuse-conversions`로 이미 만든 변환본 재사용) | 같은 회차 명령 다시 |
| AI 호출 중단(세션 종료·PC 재시작) | 응답마다 `status.json`(지시문 해시·응답 해시·모델)을 남기고, 유효한 응답은 다시 부르지 않는다 | 같은 `run` 명령 다시. 지시문이 바뀐 조각만 다시 부른다 |
| 무효 호출(웹소켓 403 등) | 1회 자동 재시도 | 남은 무효는 같은 명령을 나중에 다시 |
| **사용 한도**(Codex 사용량 초과) | 호출이 무효로 기록되고, 전부 실패면 종료 코드 3 | 묶음 실행기가 `valid/called` 비율이 80% 아래로 떨어지면 그 묶음을 멈추고 **60분 기다린 뒤 같은 명령으로 잇는다**(유효 응답은 건너뜀). 세 번 연속이면 멈추고 임무 기록에 적는다 |
| 원문 변경(학교가 공시 정정) | 변환본 해시가 바뀌면 그 문서의 AI 대상 id가 바뀐다 | 새 대상만 다시 부른다 |

다음 임무에서 만들 것(계획만, 이번에는 만들지 않음): 시도 묶음 실행기 `scripts/run_nationwide.py` — 묶음·단계별 체크포인트 파일, 위 표의 대기·재시도 규칙, 묶음별 시간·호출·무효 기록(이번 `.tmp/s20/timing.py`를 옮김).

## 5. 품질 확인을 어디에 끼우나
